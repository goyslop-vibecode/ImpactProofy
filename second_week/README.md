## 1. Выбор платформы и архитектуры хостинга

Для лендинга проекта **ImpactProofy** было решено не использовать конструкторы сайтов вроде Tilda, Carrd или Wix. Проект связан с разработкой и DevTools, поэтому было важно иметь полный контроль над сайтом и сервером.

Основные причины:

1. Возможность самостоятельно настраивать сервер и безопасность.
2. Контроль над производительностью и загрузкой сайта.
3. Возможность использовать интерактивные компоненты на Vue 3.
4. Возможность в дальнейшем расширять сайт без ограничений конструктора.

**Используемый стек:**

* **Хостинг:** VPS/VDS на Linux.
* **Веб-сервер:** Nginx.
* **HTTPS:** Let's Encrypt + Certbot.
* **Фронтенд:** Vue 3, Composition API, Tailwind CSS, SVG.

## 2. Структура лендинга

Лендинг состоит из нескольких основных блоков.

**1. Header**

Содержит логотип ImpactProofy и навигацию по основным разделам страницы: "Пайплайн", "Симулятор", "Возможности" и "Спецификация".

**2. Первый экран**

На первом экране размещены название проекта, основной слоган:

*"Смотри не на код, а на его последствия".*

Также здесь находится краткое описание продукта, кнопка перехода к демо и карточка с примером аудита Pull Request.

**3. Как работает ImpactProofy**

Работа системы показана в виде четырёх этапов:

1. Анализ Pull Request.
2. Построение графа зависимостей.
3. Проверка изменения в изолированной среде.
4. Формирование отчёта с результатами проверки.

**4. Интерактивный симулятор**

На странице можно посмотреть пример работы системы. Пользователь может выбрать один из сценариев и увидеть результат проверки изменения.

**5. Основные возможности**

В этом блоке показано отличие ImpactProofy от обычного code review: система анализирует не только изменённые строки, но и возможные последствия изменений для остальных частей проекта.

**6. Footer**

В нижней части страницы находятся информация о проекте, ссылки на репозиторий и контактные данные.

## 3. Целевые действия

На лендинге предусмотрено несколько вариантов взаимодействия с пользователем:

* запуск интерактивного демо;
* копирование команды установки CLI;
* переход в GitHub-репозиторий проекта.

Основным действием является запуск демо, чтобы пользователь мог сразу посмотреть принцип работы ImpactProofy.

---

## 4. Развёртывание на сервере

Для размещения сайта используется VPS с Debian Linux.

Файлы сайта размещены в директории:

```bash
/var/www/mdevedev-art.space/

└── index.html
```

Nginx используется для раздачи сайта и обработки HTTPS-соединений. Сертификат получен с помощью Let's Encrypt.
